# HANDOFF — как жить с сайтом STEPPESTEEL v5

## Два варианта главной (04.09.2026)

Заказчику показываются две ссылки, чтобы выбрать направление:

| Вариант | Ссылка | Что это |
|---|---|---|
| А — «Цех в работе» | https://werstrax.github.io/steppesteel-preview/ | авторский: фото цеха на первом экране, одна тёмная секция, модульная сетка решений |
| Б — «строго по ТЗ и макету» | https://werstrax.github.io/steppesteel-tz/ | белый лендинг: 10 блоков макета по порядку, плоское меню ТЗ §4, показатели с иконками |

Сборка варианта Б — переменной окружения:

```bash
VARIANT=tz node build.mjs
```

Отличаются только главная (`src/pages/home-tz.mjs`), тема
(`src/assets/css/theme-tz.css` поверх `site.css`) и меню
(`site.json → navTz`). Данные, внутренние страницы, формы и SEO — общие,
правка контента попадает в оба варианта сразу.

Что есть только в Б: лента сечений ПСУ и ПС в масштабе (`sortamentStrip`),
схемы типовых решений как листы КМ (`typicalScheme`), пиктограммы разрезов
в карточках без фото, паспорт площадки таблицей, пять шагов с иконками.
Когда заказчик выберет вариант, второй удаляется вместе с его репозиторием.

## Дизайн-система v5 «Цех в работе» (04.09.2026)

Концепция и референсы — `docs/research/05-referensy.md`. Один файл стилей
`src/assets/css/site.css`, 18 разделов, токены в начале (OKLCH, три слоя:
примитивы → семантика → компоненты; HEX только в блоке токенов — фолбэк
для старых Android). Тёмная секция = переопределение семантических
переменных на `.section--dark` — компоненты внутри перекрашиваются сами,
отдельных «тёмных» классов нет.

Главная (`src/pages/home.mjs`) по порядку макета Шамиля: первый экран
на фото цеха (`hero-photo`) → цифры-манифест (`.manifest`, четыре
проверенные цифры из `site.proof`) → модульная сетка девяти решений
(`.tiles`: флагман 2×2, решения с фото 1×1, без фото — графитовая плитка
с метаданными; порядок задан массивом `tileOrder`) → «Завод, а не
посредник» с мозаикой кадров цеха (`.mosaic`, кадры из `production.json →
sections[].photoSlot`) → шесть шагов → типовые → четыре аудитории →
объекты → о заводе (база, оборудование, скан сертификата) → CTA.

Страница решения открывается фото-хиро (`pageHero({ image })`) — если
в манифесте есть `sol-<slug>`; иначе типографический хиро. Схемы решения —
`solutions.json → items[].figures: [{ slot, caption }]` (у зернохранилищ —
`zerno-cutaway`, `zerno-node`). Медиа технологий — `tech.json →
items[].media`.

## Как поменять контент

Весь контент — в `src/data/*.json`. HTML руками не правится.

| Что поменять | Где |
|---|---|
| Телефон, WhatsApp, email, адрес, отделы | `site.json` → `contacts` |
| Навигация, CTA | `site.json` → `nav`, `navFooter`, `cta` |
| Решения (9 типов зданий) | `solutions.json` — новый тип = новый объект в `items` |
| Технологии (7 страниц) | `tech.json` |
| Производство: участки, процесс, цифры | `production.json` |
| Портфолио объектов | `portfolio.json` (поля карточки — по ТЗ §11) |
| Документы PDF | `documents.json` + файл в `src/assets/docs/` |
| Аграриям / Строителям / Проектировщикам / Партнёрам | `agrarians.json` / `builders.json` / `designers.json` / `network.json` |
| Профили ПСУ и ПС (сортамент) | `profiles.json` |
| Вопросы-ответы | `faq.json` |
| Статьи журнала | `journal.json` |
| Регио-страницы | `regions.json` |
| Калькулятор окупаемости | `payback.json` |

Поля с `_` — служебные заметки, на сайт не попадают. После правки:
`node build.mjs` → проверить локально → задеплоить.

## Как добавить объект в портфолио

Новый объект = новый элемент в `portfolio.json → items`: title, purpose,
region, size, area, steelWeight, frameType, year, prodTerm, photos[], text,
category (agro / sklady / prom / angary / modulnye / drugie). Фильтр
по категориям появится сам, когда объектов станет 4 и больше.
Выдуманных объектов на сайте не бывает — только реальные.

## Как добавить фото

Решение Рамазана 02.09.2026: ИИ-визуализаций на сайте нет. С 04.09.2026
все кадры на сайте — собственные материалы завода, вытащенные из двух
презентаций (`src/assets/docs/*.pdf`): цех, линия профилирования, резка,
сварочные посты, контроль, отгрузка, каркасы построенных объектов, рендеры
профилей и узлов, схемы зернохранилища, скан сертификата. Снятые
визуализации kie.ai лежат в `src/assets/img/raw/viz-archive/raw-kie/`
(в сборку не попадают, обратно не возвращать).

Слоты, где кадра ещё нет (стоит плашка «Фото в обработке»):

| Слот | Где | Что снять |
|---|---|---|
| `sol-sklady`, `sol-ovoshchehranilishcha`, `sol-sto-avtoparki`, `sol-sportivnye-obekty`, `sol-modulnye-zdaniya` | плитки решений на главной, хиро и карточки /resheniya/ | построенный объект этого типа, общий план |
| `obj-<slug>` / `portfolio.json → photos` | объекты портфолио | готовое здание + монтаж |
| `hero-photo` (замена) | первый экран главной | сейчас кадр из презентации с размытой левой половиной; идеал — широкий кадр цеха 16:9, ≥2400px |

Заполненные слоты (заменяются кадром под тем же именем): `hero-photo`,
`sol-zernohranilishcha` (реальный объект), `sol-angary`,
`sol-proizvodstvennye-zdaniya`, `sol-zdaniya-dlya-tekhniki` (рендер
навеса — помечен «Визуализация» через `coverViz`), `prod-*` ×9,
`tech-hub`, `tech-lstk-1/2`, `tech-boltovye-1`, `zerno-cutaway`,
`zerno-node`, `aud-designers`, `aud-partners`, `cert-p1..4`.

Порядок: исходник (jpg/png, ≥1400px по ширине) в `src/assets/img/raw/` →
`python tools/optimize_images.py <имя-слота>` → `node build.mjs`.
Плашка исчезает автоматически.

⚠️ Оптимизатор: под одним именем в `raw/` должен лежать ОДИН файл
(два — `x.jpg` и `x.png` — дают непредсказуемый выбор). `--force` вместе
со списком имён ПЕРЕСОЗДАЁТ манифест только из этих имён (остальные
записи пропадут) — для замены одного кадра сначала удалить его файлы
`src/assets/img/<имя>-*` и запустить без `--force`.

## Формы и приём файлов (ТЗ §17) — РЕШЕНО 30.08.2026

Решение Рамазана: максимально просто, никаких баз и кабинетов — те, кто
принимает заявки, работают в WhatsApp и почте, туда заявки и приходят.

Как работает: форма собирает заявку в текст и открывает WhatsApp
посетителя (+ honeypot от спама); файл проекта посетитель прикладывает
в чате WhatsApp или шлёт на steppe.steel@gmail.com — форма честно
подсказывает это сама. Никакого бэкенда, ломаться нечему.

Если когда-нибудь понадобится приём файлов прямо с сайта: вписать URL
обработчика в `site.json → forms.endpoint` — форма сама перейдёт на POST
multipart (поле `project` — файл, `message` — текст заявки), подсказка
сменится автоматически. Ключи сервиса — только на сервере, не в git.

## CMS (ТЗ §22) — РЕШЕНО 30.08.2026

Решение Рамазана: без CMS. Контент живёт в `src/data/*.json`, правки —
по этому HANDOFF (таблица «Как поменять контент» выше) либо по запросу
разработчику. Пункт ТЗ §22 закрывается инструкцией + сопровождением —
проговорить это с заводом при сдаче.

## Аналитика (ТЗ §24)

`site.json` → `analytics.yandexMetrikaId` / `googleAnalyticsId` — вписать
ID, код подключится сам. События (уходят и в Метрику, и в GA):

| Событие | Когда |
|---|---|
| `calc_submit` | отправка формы «Получить расчёт» (+ параметр purpose) |
| `partner_submit` | отправка партнёрской формы на /partneram/ |
| `wa_click` | клик по любой кнопке/ссылке WhatsApp |
| `tel_click` | клик по номеру телефона |
| `pdf_download` | клик по любому PDF (+ имя файла) |

## Языковые версии (ТЗ §25)

Архитектура заложена: казахская версия включается созданием папки
`src/data/kk/` с переведёнными копиями JSON (можно переводить по одному
файлу — непереведённые возьмутся из русской версии). Сборка сама соберёт
зеркало `/kk/...` с теми же слагами и расставит hreflang на обеих версиях.
Английская — так же (`src/data/en/` + код языка в `LANGS` в build.mjs).
Пока папки нет — собирается только русская версия, hreflang не выводится.

## Мобильная панель (ТЗ §18)

Липкая панель «Позвонить · WhatsApp · Получить расчёт» показывается
на экранах ≤720px после прокрутки первого экрана и прячется у футера.
Без всплывающих окон — ТЗ их запрещает.

## Домен steppesteel.kz

`site.json` → `url: "https://steppesteel.kz"`, `basePath: ""`. CNAME лежит
в `src/assets/static/` и сборкой кладётся в корень `dist/` — не удалять,
иначе GitHub Pages отвяжет домен. DNS: 4 A-записи GitHub Pages на apex +
CNAME `www` → werstrax.github.io. Sitemap: https://steppesteel.kz/sitemap.xml.

⚠️ По правилам зоны .kz сайт должен хоститься на сервере в РК. Если от
регистратора придёт предупреждение — на переезд 10 дней: залить `dist/`
на казахстанский хостинг и перевести A-записи. Код менять не нужно.

## Превью для заказчика и заглушка на домене (02.09.2026)

Пока сайт не наполнен фото, на домене steppesteel.kz стоит фирменная
заглушка «Сайт временно недоступен» (`src/holding/index.html`, скопирована
в корень как index.html и 404.html + CNAME + favicon + .nojekyll). Рабочая
версия v4 показывается заказчику на превью-адресе (noindex, без CNAME):

**https://werstrax.github.io/steppesteel-preview/**

Обновить превью:

```bash
PREVIEW=1 SITE_URL=https://werstrax.github.io/steppesteel-preview BASE_PATH=steppesteel-preview node build.mjs
# содержимое dist/ → репозиторий werstrax/steppesteel-preview (ветка main, корень) → push
# BASE_PATH пишем БЕЗ ведущего слэша: Git Bash на Windows подменяет «/preview»
# на путь установки (C:/Program Files/Git/preview). Сборщик нормализует значение сам.
```

Вернуть сайт на домен (когда фото добавлены и Шамиль одобрил): обычный
деплой ниже — корень репо steppe-steel заменяется содержимым обычной
сборки `node build.mjs` (без переменных окружения).

## Деплой на GitHub Pages (текущий)

```bash
node build.mjs && node tools/check.mjs
# скопировать dist/* в корень репо (заменив старые файлы сборки)
git add -A && git commit -m "content: ..." && git push
```

Со старых URL v1 (`zernohranilishcha.html`) и v3 (`/katalog/…`, `/uslugi/…`,
`/zayavka/`, `/partnyoram/`, `/predstavitelyam/`, `/process/`) сборка
автоматически генерирует страницы-редиректы — не удалять.

## Что проверять после правок

1. `node tools/check.mjs` — 0 ошибок.
2. `node tools/test_functional.mjs` — все проверки ok.
3. `node tools/audit_mobile.mjs` — переполнений нет.

## Резервное копирование и почта (ТЗ §26)

Бэкап — сам git-репозиторий (история всех версий сайта и данных). Что в git
не попадает и должно лежать отдельно (облако/архив): исходники картинок
`src/assets/img/raw/`, исходники PDF (pptx) и ключи сервисов. При переезде
на казахстанский хостинг — регулярная копия `dist/`.

Корпоративная почта на домене: у регистратора (hoster.kz) уже есть MX
на mail.steppesteel.kz — завести ящики (info@, sales@) в панели хостинга или
подключить Google Workspace/Zoho, добавить SPF/DKIM, затем заменить
`site.json → contacts.email`. До этого работает steppe.steel@gmail.com.

## Технологии: схемы и фото профилей (ТЗ §13)

`tech.json → items[].media`: `[{ "slot": "tech-lstk-1", "caption": "Сечение ПСУ" }]`.
Кадр под именем slot → `optimize_images.py <slot>` → страница покажет его
с подписью; без кадра — плашка «готовится».

## Портфолио: несколько фото и монтаж (ТЗ §11)

`portfolio.json → items[].photos` — все фото объекта (первое — обложка),
`montage` — фото монтажа. Второе и далее показываются галереей с лайтбоксом.

## Команда (ТЗ §22)

`src/data/team.json → items`: name, role, photo. Появятся записи — блок
«Команда» выведется на /o-zavode/ сам.

## Заявки: откуда пришёл посетитель (ТЗ §24)

В текст каждой заявки добавляется строка «Источник: utm · с <реферер> ·
страница <url>», те же данные уходят параметром `source` в события
`calc_submit` / `partner_submit`. UTM сохраняются с первого визита в сессии.
